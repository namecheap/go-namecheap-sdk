# CI/Release Automation for go-namecheap-sdk

Date: 2026-07-27
Template repo: [go-spaceship-sdk](https://github.com/namecheap/go-spaceship-sdk) (same shape: pure Go library, no binaries)

## Goal

Stand up the same semi-automated, maintainer-gated release pipeline the sibling
repos use: Dependabot with Conventional Commit prefixes, release-please for
version bumps/changelog/tagging, PR-title enforcement, and release
documentation. Releases stop being manual hand-tagging.

## Decisions (agreed 2026-07-27)

- **Mirror go-spaceship-sdk**, not terraform-provider-namecheap (no GoReleaser —
  a Go library release is just a tag + GitHub release).
- **Root module only.** release-please manages `github.com/namecheap/go-namecheap-sdk/v2`
  (current version 2.7.0). The nested `otelnamecheap` module keeps manual
  tagging (`otelnamecheap/vX.Y.Z`).
- **Remove `auto-release.yml`** — the weekly blind-tagging cron is fully
  superseded and would race release-please for the same commits.
- **GitHub App auth** for versioning.yml: `vars.NC_SDK_RELEASE_CLIENT_ID` +
  `secrets.NC_SDK_RELEASE_PRIVATE_KEY`. Default `GITHUB_TOKEN` is not usable:
  events it authors do not trigger workflows, so the Release PR would never get
  CI runs and required checks would deadlock it.

## Changes

### 1. `.github/dependabot.yml` (replace existing)

Spaceship's config: weekly; gomod → `fix(deps):` (releasing type — module bumps
change what consumers `go get`), github-actions → `ci(deps):` (non-releasing —
CI-only). Keep the explanatory comments. Repo-specific addition: `vendor: true`
on the gomod entry because this repo vendors dependencies; without it a bump
PR leaves `vendor/` inconsistent and fails CI. Root module only (as today).

### 2. `.github/workflows/pr-title.yml` (new)

Exact copy from go-spaceship-sdk: `amannn/action-semantic-pull-request` pinned
to SHA `48f256284bd46cdaab1048c3721360e808335d50` (verified = v6.1.1), types
`feat fix docs chore refactor test ci perf build revert`. PRs are squash-merged
(already the repo setting), so the PR title becomes the commit subject that
release-please classifies.

### 3. release-please (new)

- `.release-please-config.json`: spaceship's, minus the pre-1.0
  `bump-minor-pre-major` / `bump-patch-for-minor-pre-major` flags (repo is at
  2.7.0). Keeps `release-type: go`, `include-v-in-tag`, changelog sections
  (feat/fix/docs/deps), single package `"."`.
- `.release-please-manifest.json`: `{".": "2.7.0"}`.
- `.github/workflows/versioning.yml`: spaceship copy adapted to `master`;
  triggers on `workflow_run` of `CI` (name matches this repo's ci.yml) with
  `conclusion == 'success'` guard, plus `workflow_dispatch`; GitHub App token
  via `actions/create-github-app-token`; `googleapis/release-please-action@v5`
  (same pinned SHAs as spaceship).

### 4. Remove `.github/workflows/auto-release.yml`

### 5. `CHANGELOG.md`

Remove the empty `[Unreleased]` section; adjust the header to say entries are
generated by release-please from Conventional Commits going forward.
release-please prepends new entries above the existing hand-written history.

### 6. Documentation

- **`RELEASE.md` (new)**: adapted from spaceship — master branch, `/v2` module
  path, flow (PR → Release PR → maintainer merge → tag), required
  configuration table (App var/secret), manual/emergency release steps, and an
  `otelnamecheap` section: tagged manually as `otelnamecheap/vX.Y.Z`; the
  existing `votelnamecheap/v0.1.1` tag is malformed and invisible to the Go
  module proxy (v0.1.1 is effectively unreleased).
- **`CONTRIBUTING.md`**: add Conventional Commit PR-title convention; rewrite
  the Release section to point at RELEASE.md.
- **`CLAUDE.md`** (AGENTS.md symlinks to it): add commit conventions and a
  release-flow blurb.

## Manual follow-ups (owner: maintainer, documented in RELEASE.md)

1. Install the org release GitHub App on this repo; set
   `NC_SDK_RELEASE_CLIENT_ID` (variable) and `NC_SDK_RELEASE_PRIVATE_KEY`
   (secret).
2. Optionally disable rebase merges (PR-title scheme assumes squash).
3. Optionally re-tag otelnamecheap v0.1.1 as `otelnamecheap/v0.1.1`.

## Out of scope

- GoReleaser / release.yml (nothing to build for a library).
- release-please coverage for `otelnamecheap` (would need multi-package config
  with `/` tag separator; revisit if the otel module gets regular releases).
- Dependabot for `otelnamecheap/go.mod`.

## Verification

- `actionlint` on workflows; JSON/YAML validity.
- `make format && make check && make lint && make test-unit-quiet` — expected
  no-ops (no Go code changes).
- Post-merge (manual): confirm Dependabot PRs use the new prefixes, a
  `fix:`/`feat:` merge opens the Release PR, and merging it tags `vX.Y.Z`.
